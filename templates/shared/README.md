# Native Shopify storefront apps

A SwiftUI iOS app (`ios/`, iOS 17+) and a Jetpack Compose Android app (`android/`, minSdk 26) for one Shopify store, generated by Argon. Both read the Storefront API (`2026-10`) and check out with Shopify's Checkout Kit.

## Run

- **iOS** (on a Mac): open `ios/App.xcodeproj` in Xcode 16+, pick a simulator, press Run.
- **iOS without a Mac**: see [below](#ios-without-a-mac-xtool).
- **Android**: open `android/` in Android Studio and press Run, or `cd android && ./gradlew assembleDebug`.

### iOS without a Mac (xtool)

[xtool](https://xtool.sh) builds the app on Linux or Windows (through WSL) and installs it on an iPhone over USB. `ios/Package.swift` and `ios/xtool.yml` are there for it; they build the same sources as the Xcode project.

1. Install xtool and its prerequisites, following its [installation guide](https://xtool.sh/documentation/xtool/installation-linux): Swift, `usbmuxd`, the `Xcode.xip` download for the iOS SDK, and `xtool setup` to sign in with an Apple ID.
2. Connect the iPhone by USB, trust the computer, and turn on Developer Mode (Settings → Privacy & Security).
3. Run `cd ios && xtool dev`.

xtool has no build settings, so the app reads its per-store values from `ios/Config.xcconfig`, which `xtool.yml` copies into the app. `xtool.yml` also lists every GraphQL document: when you add a query, add its file there too. With a free Apple ID the installed app expires after 7 days and xtool prefixes the bundle ID.

## Configuration

One key list, two files with the same key names. Edit, then rebuild.

| Key | Meaning |
|---|---|
| `SHOP_DOMAIN` | The store's `*.myshopify.com` domain, no `https://` |
| `STOREFRONT_TOKEN` | Public Storefront API token from the Headless channel |
| `CUSTOMER_CLIENT_ID` | Customer Account API client ID (client type Public (mobile app)). Empty hides login |
| `SHOP_ID` | Numeric shop ID; the login callback is `shop.<SHOP_ID>.app://callback` |
| `API_VERSION` | Storefront API version, `2026-10` |
| `APP_NAME` | Display name under the app icon |
| `BUNDLE_ID` | iOS bundle ID / Android `applicationId` |
| `PDP_METAFIELDS` | Product metafields to list on the product page, comma-separated `namespace.key` (e.g. `custom.material,custom.care`). Empty shows none |

- iOS: `ios/Config.xcconfig` (`KEY = value`)
- Android: `android/shopify.properties` (`KEY=value`)

With an empty `STOREFRONT_TOKEN` on any store other than `mock.shop`, the app shows a setup screen naming the missing key.

## Demo store (`mock.shop`)

`mock.shop` has no metaobjects, so Home shows the fallback home. It also doesn't implement `nodes(ids:)`, so the Wishlist tab stays empty there. It works on real stores.

## Edit the home screen

In Shopify admin go to **Content → Metaobjects → Mobile screen → Home**. The home screen is an ordered list of sections: *Mobile banner*, *Mobile products* and *Mobile collections* entries. Add, reorder or edit them and save; the apps pick it up with no release. If the entry is missing or empty, the apps show a fallback home built from the store's brand, collections and products.

## Store prerequisites

- **New customer accounts** are on (Settings → Customer accounts), or login won't work.
- The **storefront password is off** (Online Store → Preferences), or Checkout Kit can't open checkout.
- **Products and collections are available to the Headless storefront's sales channel**, and its Storefront API keeps the metaobject read permission, or the app shows an empty or fallback home.
- **Collection and search filters** appear only after the Search & Discovery app has filters configured.

## Publishing

- Ship each client's app from **the client's own** Apple Developer and Google Play Console accounts (Apple guideline 4.2.6: an app built from a template or generator must be submitted by the owner of its content). Add the agency as a team member.
- Both stores require an in-app way to start **account deletion**. The Account screen's *Delete account* opens `https://<SHOP_DOMAIN>/pages/contact`; make sure that page exists on the store and that someone handles the requests.

## Troubleshooting

If Argon stopped while creating the home screen content, it can leave some entries behind. Delete the *Mobile banner*, *Mobile collections*, *Mobile products* and *Mobile screen* entries it created (Content → Metaobjects) before running it again; otherwise the re-run fails on the taken handles.
