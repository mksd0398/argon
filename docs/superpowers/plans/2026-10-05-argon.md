# Argon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npx @mksd0398/argon my-store-app` generates a buildable SwiftUI iOS app and Jetpack Compose Android app for one Shopify store, with metaobject-driven home sections, PLP, PDP, cart + Checkout Kit, search, menu, wishlist and Customer Account login.

**Architecture:** A plain ESM Node CLI (Nitrogen style) copies `templates/{android,ios}` into a new project, writes resolved GraphQL documents from `contract/` into both apps, and writes one per-store config file per platform. Admin provisioning (metaobject definitions + seed) runs through `shopify store auth` / `shopify store execute`. Both apps call the Storefront API directly with a hand-written client and use Checkout Kit for checkout.

**Tech Stack:**
- **CLI:** Node ≥ 18 ESM, `prompts`, `node --test`.
- **Android:** Kotlin, Compose, Navigation Compose, OkHttp, kotlinx-serialization, Coil 3, DataStore, androidx.browser, `com.shopify:checkout-sheet-kit:3.6.3`.
- **iOS:** Swift 5.10+/SwiftUI on iOS 17, URLSession, `checkout-sheet-kit-swift` 3.9.1 (`ShopifyCheckoutSheetKit`), XCTest.

**Spec:** `docs/superpowers/specs/2026-10-05-argon-design.md`

## Global Constraints

**Versions and dependencies**
- Storefront API version `2026-10`. Endpoint `https://<SHOP_DOMAIN>/api/2026-10/graphql.json` with header `X-Shopify-Storefront-Access-Token` (omit the header when the token is empty).
- iOS deployment target 17.0. Android minSdk 26, targetSdk 36, compileSdk 36.
- The only Shopify SDK is Checkout Kit. No Mobile Buy SDK, no Apollo, no DI framework.
- CLI runtime dependency: `prompts` only.

**Store-facing names**
- Metaobject types: `mobile_screen`, `mobile_banner`, `mobile_products`, `mobile_collections`. The home entry handle is `home`.
- Login: scope `openid email customer-account-api:full`, PKCE S256, redirect `shop.<SHOP_ID>.app://callback`.

**Generated project**
- Config keys, identical on both platforms: `SHOP_DOMAIN`, `STOREFRONT_TOKEN`, `CUSTOMER_CLIENT_ID`, `SHOP_ID`, `API_VERSION`, `APP_NAME`, `BUNDLE_ID`, `PDP_METAFIELDS`.
- Demo store: `SHOP_DOMAIN=mock.shop`, empty token, `SHOP_ID=68817551382`.
- Layout: `my-store-app/{AGENTS.md, CLAUDE.md, README.md, .gitignore, android/, ios/}`.
- The Android source namespace is fixed at `app.storefront`. Only `applicationId` varies. The iOS target is `App`. The `.xcodeproj` is never edited by the CLI.

**Templates**
- Templates never contain dotfiles; npm strips them. `gitignore` is renamed to `.gitignore` on copy.
- After copy the CLI sets `chmod 755` on `android/gradlew`.

**Safety**
- The CLI never stores Admin credentials and never changes Shopify CLI config.
- No task runs provisioning against a real store or publishes anything.
- **Session log:** before finishing, every implementer appends one row to `C:\Users\arjun\mksd\create-shopify-app-storefront\SESSION_LOG.csv` (`date,project,task,start_time,end_time,status`, task double-quoted and prefixed `subagent:`, project `create-shopify-app-storefront`, IST `HH:mm`).

## Review Focus

1. **Store domain typed loosely.** Inputs like `https://Nalli.myshopify.com/`, `nalli` or `nalli.com` should normalise to `nalli.myshopify.com`. A custom domain should be rejected for `--store`, with a hint to use the myshopify domain. Tested in Task 1.
2. **Menu and banner links on other hosts.** A link pointing at the store's custom primary domain or its myshopify domain, with query strings, trailing slashes or locale prefixes (`/en-in/products/x`), should route in-app. Any other host opens in the browser. Tested in Tasks 6 and 11.
3. **A selection with no matching variant** (deleted variant, or more than 250 variants) shows "Unavailable" and disables Add to cart without crashing. Tested in Tasks 6 and 11.
4. **A stored cart ID that Shopify returns as `null`** (completed or expired) shows an empty cart, and the next add creates a new cart with no error shown. Tested in Tasks 9 and 12.
5. **A home metaobject with deleted references, unknown section types or zero renderable sections** skips the bad sections, and falls back to the in-code home when nothing is left. Tested in Tasks 6 and 11.
